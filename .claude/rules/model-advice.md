# Model advice

- At the start of a task, or when the work changes character, say in ONE line if another model would clearly be better or cheaper:
  mechanical edits, renames, formatting, simple lookups -> a smaller, cheaper model; architecture, hard debugging, security review, large refactors -> a stronger model.
- Say it only when the switch would matter. If the current model fits, stay silent. No lecture; the user switches with `/model`.
