# Spec gate

- When a task is given that will change code, first use the `spec-gate` skill and follow its verdict.
- Do not implement a task that changes behavior until its spec or proposal is approved.
- If the task brings no logical change, proceed and say in one line: "No spec needed: <reason>".
- If the task went through brainstorming first, use the approved design as the basis for the spec.
